# QuestLog

Твои задачи — как квесты на пиксельной доске: статусы, перетаскивание карточек
между колонками, приоритеты, исполнители, комментарии, вложения. Работает
одинаково на Windows и Linux — в виде **настольного приложения с иконкой
в трее** либо как обычная страница в браузере.

Никаких облачных аккаунтов, никакого интернета для работы не требуется —
всё хранится у вас на диске.

## Возможности

- Доска с колонками (по умолчанию: Бэклог → Todo → In Progress → Done → Cancelled),
  колонки можно добавлять, переименовывать и удалять.
- Перетаскивание задач между колонками и внутри колонки (drag-and-drop).
- Приоритет (🔴 высокий / 🟠 средний / ⚪ обычный / 🔵 низкий), теги (с готовыми
  подсказками — Срочно, Работа, Личное, Идея, Баг, Покупки, добавляются в один
  клик), срок выполнения.
- Назначение исполнителя — участники добавляются в один клик, платформа
  сразу готова к работе командой, когда это понадобится.
- Комментарии к задаче с указанием автора.
- Вложения: загрузка файлов выбором или перетаскиванием в карточку задачи,
  скачивание и превью картинок, PDF и текстовых файлов прямо в приложении.
- Несколько досок (проектов) на выбор в шапке.
- **Доска = проект.** Клик по названию доски в шапке открывает компактную
  панель проекта справа (как панель календаря): колонки при этом не
  сдвигаются и не сжимаются, на доске ничего нового не появляется.
  Переименовать проект можно там же, в разделе «Обзор».
  В панели три раздела:
  - **Обзор** — название и описание проекта, а также переключатель
    доступа к документации;
  - **Обновления** — история изменений проекта в виде компактного
    changelog: дата, заголовок и текст. Записи добавляются, правятся и
    удаляются теми же кнопками, что и комментарии к задаче (прав по
    ролям в приложении нет — см. «Совместная работа»);
  - **Документы** — своё хранилище файлов у каждой доски: загрузка
    выбором файла или перетаскиванием в панель, просмотр поддерживаемых
    форматов внутри приложения (картинки, PDF, текст — тем же
    просмотрщиком, что и у вложений задачи), скачивание файла,
    выгрузка всей документации одним архивом («Отдать досье», см. ниже),
    переименование и удаление. Для каждого файла видны название, тип,
    размер и дата изменения.
  - **Создание и правка текста на месте** («+ создать»). Панель проекта
    умеет не только принимать готовые файлы: заметку можно написать прямо
    здесь, не выходя в проводник. Кнопка создаёт настоящий файл в папке
    доски — источником правды остаётся диск, а не база, поэтому такой
    документ так же скачивается, переименовывается и редактируется
    снаружи. Формат в задаче не спрашивается: документ всегда текстовый,
    расширение подставляет приложение.
    У открытого текста есть кнопка «Править»: блок чтения меняется на
    `<textarea>`, `Ctrl+S` сохраняет. Если файл на диске изменился, пока он
    был открыт, сохранение отклоняется — чужие правки не затираются молча.
    Изображения и `.ods`, как и раньше, только скачиваются.
- **Публичный доступ по ссылке.** В разделе «Обзор» переключатель
  «Только участники / Доступна по публичной ссылке». Во включённом
  состоянии появляется ссылка вида `/public/docs/<токен>` и кнопка
  «Копировать»: по ней открывается страница с описанием, обновлениями и
  списком документов проекта, а файлы скачиваются. Это не система прав
  доступа, а разделяемая ссылка: она открывается любому, у кого ссылка
  есть, и перестаёт работать, как только переключатель выключен
  (ссылка при этом сохраняется — после повторного включения заработает
  снова). Угадать токен нельзя, но и отозвать старую ссылку, не выключив
  доступ, тоже нельзя.
- **«Отдать досье»** — одно действие вместо россыпи экспортов. Нажали и
  получили архив, который читается без QuestLog: самодостаточная страница
  отчёта со встроенными стилями (её можно распечатать в PDF), `обновления.md`,
  `события.md`, `задачи.txt` и сами документы. Отдали архив человеку — он
  открыл папку и прочитал проект, даже если приложение закрыто, а QuestLog у
  него нет. `задачи.txt` — это тот же список по колонкам, но обычным текстом:
  его можно вставить в письмо, не таская HTML. Доступно и во вкладке «Обзор»,
  и во вкладке «Документы» — архив один и тот же. Рядом тихая ссылка
  «открыть отчёт в браузере», если нужен быстрый взгляд без скачивания.
- **Лента событий проекта** (вкладка «События»). Записи появляются сами из
  тех же действий, что меняют доску: создание, правка, удаление и перенос
  задач, работа с колонками, обновления, документы, переименование доски и
  настройки публичного доступа. Событие не может разойтись с реальностью —
  записать его можно лишь вместе с изменением. Автор берётся из участника,
  выбранного в нижней панели.
  **Пересказ за период** («С 20.09: закрыто 22 задачи, вышло 1 обновление,
  приложено 4 документа») стоит над списком: сначала «что изменилось», потом
  детали того, как именно. Пересказ копируется в буфер обмена значком в его
  углу — одной кнопкой, без выделения текста.
- **Зависшие задачи** — раздел в досье: всё, что не в завершающей колонке
  и при этом без исполнителя, с просроченным сроком или без движения больше
  14 дней. По причинам видно, за что браться: у каждой строки написано,
  в чём именно она зависла.
- **Палитра команд** `Ctrl`/`Cmd`+`K`: доски, темы, новая задача, открытие
  панели проекта. Поиск по названию, стрелки и `Enter`; `Esc` закрывает.
  Видимого элемента в интерфейсе не имеет — только клавиша.
- Поиск по названию, описанию и тегам (клавиша `/`).
- Кнопка **«+ Задача»** в шапке открывает форму создания: название
  (в фокусе), статус/приоритет/исполнитель/срок, теги и описание.
  Секции подзадач, вложений и комментариев появляются позже, в карточке
  уже созданной задачи. Задача записывается в базу только по кнопке
  **«Создать»** (или Enter в названии); «Отмена» и Escape ничего
  не оставляют на доске. Статус/колонку по умолчанию «Бэклог» можно
  сменить полем «Статус». Быстрое добавление колонки — прямо на доске
  (без всплывающего окна): поле появляется на месте кнопки, Enter добавляет.
- Изменения в карточке задачи (заголовок, описание, приоритет, исполнитель,
  срок, теги, статус) сохраняются только по нажатию кнопки «Сохранить» —
  она активна, только если что-то действительно изменилось. Комментарии и
  вложения добавляются/удаляются сразу своими кнопками, без «Сохранить».
- Две темы оформления, переключаются селектором в нижней панели и
  запоминаются (`localStorage`):
  - **Ретро** (по умолчанию) — пиксельный терминальный интерфейс: оливковый
    фон, толстые чёрные рамки, острые углы, моноширинный шрифт;
  - **Плакат** — печатный агитплакат: бумага цвета слоновой кости, изумрудные
    плашки, алая лента, золотая отводка, конденсированный гротеск в
    заголовках и засечки в тексте.
- Подзадачи используют тематические чекбоксы, а иконки интерфейса
  (комментарии, вложения и действия) хранятся централизованно в
  `static/js/core/icons.js`.
- Фильтр «Мои задачи» и явный выбор «Я: …» (от чьего имени вы работаете —
  влияет на фильтр и на автора новых комментариев) — в нижней панели.
- Горячие клавиши: `/` — фокус на поиске, `N` — новая задача,
  `Ctrl`/`Cmd`+`K` — палитра команд, `Alt+M` — фильтр «Мои задачи», `Esc` —
  закрыть модалку, панель проекта или отменить инлайн-добавление.
- В панели проекта: `Enter` и пробел на названии доски открывают панель,
  стрелки `←`/`→` и `Home`/`End` переключают её вкладки, `Ctrl`/`Cmd`+`Enter`
  сохраняет описание или обновление.
- Импорт задач из старой версии TodoTray (GTK-приложения).
- Массовый перенос задач по тегу на другую доску (кнопка
  «Перенос» в шапке): выбирается тег и целевая доска —
  задачи переносятся только с текущей доски. При пустом
  поле колонки распределяют по колонкам с теми же названиями.
  Правый клик по карточке → «Перенести на доску…» — то же
  самое, но для одной задачи.

## Установка и запуск

Нужен установленный Python 3.9+ (на Windows — с сайта python.org, отметьте
галочку "Add python.exe to PATH" при установке; на Linux обычно уже стоит).

### Режим настольного приложения (окно + трей) — рекомендуется

Это основной режим: приложение живёт в системном трее, отдельный сайт
в браузере не нужен.

**Windows:** дважды кликните `run_desktop.bat`.

**Linux:**

```bash
chmod +x run_desktop.sh
./run_desktop.sh
```

Что даёт этот режим:

- приложение открывается в собственном окне (не вкладка браузера);
- иконка в системном трее — окно можно закрыть (крестиком), при этом
  приложение остаётся работать в трее и открывается повторным кликом
  по иконке или из её меню;
- меню трея: «Открыть QuestLog», «Новая задача» (сразу открывает окно
  создания задачи), «Папка с данными», «Выход»;
- пункт **«Запускать при входе в систему»** включает автозапуск при логине
  (Windows: ярлык в папке автозагрузки, Linux: `~/.config/autostart/`);
- повторный запуск (например, ещё один клик по ярлыку) не создаёт вторую
  копию, а поднимает уже открытое окно;
- на Windows `run_desktop.bat` запускает приложение через `pythonw.exe` и
  `start`, отдельным процессом от консоли — можно закрыть окно PowerShell
  или cmd, из которого был запущен `.bat`, и QuestLog продолжит работать
  в трее (если запустить `python desktop.py` вручную прямо в терминале,
  без `start`, то закрытие терминала завершит и процесс — используйте
  `run_desktop.bat`, ярлык автозапуска или `start "" pythonw desktop.py`).

Стартовать свёрнутым в трей (удобно вместе с автозапуском):

```
python desktop.py --hidden
```

Чтобы совсем не видеть консольного окна на Windows, запускайте через
`pythonw.exe` (именно его использует автозапуск).

На Linux для иконки в трее нужен установленный AppIndicator/GTK
(`gir1.2-ayatanaappindicator3-0.1` на Debian/Ubuntu, `libappindicator-gtk3`
на Fedora). Без него приложение работает как обычное окно.

### Режим браузера

Если хотите открыть доску в браузере — это тоже доступно:

```bash
./run.sh        # Linux / macOS
run.bat         # Windows
```

и откройте `http://127.0.0.1:8420`.

Если что-то пошло не так со скриптом, можно запустить вручную:

```bash
pip install -r requirements.txt
python server.py        # режим браузера
python desktop.py       # режим окна + трей
```

## Сборка в один файл

Обычный запуск требует Python и зависимости. Если нужен переносимый
`.exe`, который запускается двойным щелчком и ничего не требует:

```bash
pip install pyinstaller
python build_exe.py
```

На выходе — `dist/QuestLog.exe` (один файл, около 22 МБ, без консоли).
Внутри упакован сам сервер, статика и `waitress`. Данные при этом
**остаются на месте** — в `~/.questlog/`, то есть переносится программа, а
не проект: перенесли `.exe` на другой компьютер, скопировали папку
`.questlog` — и получили те же доски.

Каталоги `dist/` и `build/` в git не попадают.

## Где хранятся данные

- База задач: `~/.questlog/taskboard.db` (SQLite-файл)
- Вложения: `~/.questlog/attachments/`
- Документы проектов: `~/.questlog/documents/<id доски>/` — у каждой
  доски своя папка, на диске файлы лежат под случайными именами,
  а пользовательские хранятся в базе

На Windows `~` — это `C:\Users\<Имя>\`. Чтобы сделать резервную копию,
достаточно скопировать всю папку `.questlog`. Чтобы перенести данные на
другой компьютер — скопируйте эту же папку в `~/.questlog/` на новой машине.

## Совместная работа (когда понадобится команда)

Сейчас платформа рассчитана на запуск на одном компьютере, но модель данных
уже полностью готова к нескольким участникам: у задач есть исполнитель,
у комментариев — автор, участники управляются в модалке «Участники» (кнопка
в нижней панели).

Когда возникнет необходимость работать вместе с другими людьми по сети, есть
два пути развития:
1. **Общий сервер в локальной сети** — запустить `server.py` на одном
   компьютере (например, `app.run(host="0.0.0.0", ...)` вместо `127.0.0.1`),
   и коллеги открывают `http://<ваш-IP>:8420` в браузере в той же сети.
2. **Полноценный многопользовательский режим** — добавить простую
   аутентификацию (логин/пароль или токены) поверх уже существующих API.

Оба варианта не потребуют менять модель данных — только сетевую часть.

## Структура проекта

```
QuestLog/
  server.py             — backend: Flask + SQLite, вся бизнес-логика и REST API
  desktop.py            — режим настольного приложения: окно (pywebview) + трей (pystray)
  import_todo_tray.py   — импорт данных из старого TodoTray
  requirements.txt      — зависимости: Flask, waitress, pywebview, pystray, pillow
  check_js.py           — проверка синтаксиса JS-модулей (см. «Перед коммитом»)
  build_exe.py          — сборка настольного приложения в один .exe (PyInstaller)
  tests/                — тесты API на pytest (см. «Тесты»)
  .gitattributes        — переводы строк: текстовые файлы хранятся в LF
  scripts/pre-commit    — git-хук, запускающий check_js.py перед коммитом
  run.sh / run.bat      — запуск режима браузера в один клик
  run_desktop.sh / run_desktop.bat — запуск режима окна + трей в один клик
  static/
    index.html          — разметка интерфейса + отчёт о фатальной ошибке загрузки
    style.css           — оформление (обе темы, стили чекбоксов и иконок)
    js/
      core/             — инфраструктура: API, DOM, форматирование, модалки, тосты, иконки
        file-preview.js         — просмотрщик файлов (общий для вложений и документов)
      domain/           — состояние приложения и загрузчик данных
      ui/               — интерфейс: доска, карточки, модалки, календарь, участники
        task-card.js            — карточка и контекстное меню (только вид)
        context-menu-actions.js — что делают пункты меню (изменение данных)
        project-drawer.js       — панель проекта: оболочка, вкладки, обзор
        project-updates.js      — история обновлений проекта (changelog)
        project-docs.js         — документы проекта: загрузка, список, скачивание
        project-events.js       — лента событий и пересказ за период
        command-palette.js      — палитра команд Ctrl+K
        theme.js                — выбор темы оформления и её запоминание
```

## Темы оформления
Тема — это только CSS. Всё, чем одна тема отличается от другой, лежит в
`static/style.css` под селектором `html[data-theme="…"]`; JS лишь ставит этот
атрибут на `<html>` и запоминает выбор в `localStorage` (ключ `tb_theme`).

Как добавить третью тему:
1. `<option value="имя-темы" data-icon-text="…">Подпись</option>` — в
   `#theme-select` в `static/index.html` (список тем читается из разметки);
2. блок `html[data-theme="имя-темы"]` в `static/style.css` — по образцу
   «Плаката»: сначала токены (`--bg`, `--surface`, `--accent`, шрифты),
   затем — при желании — акценты отдельных элементов (шапка, колонка,
   карточка, модалка);
3. эмодзи для подписи в списке — в `ICON_TEXT` (`static/js/core/icons.js`).

Правки в JS при этом не нужны. Тема по умолчанию — та, что объявлена в `:root`
(«Ретро»): неизвестное значение `data-theme` просто оставляет её токены.

## Тесты
Логика backend покрыта тестами на `pytest`. Они работают на временной базе
и не трогают задачи в `~/.questlog`:

```bash
pip install -r requirements.txt
python -m pytest
```

Что проверяется: создание задачи и её поля, валидация срока (`2025-02-31`
не пройдёт), перенос задачи между колонками и досками с пересчётом порядка,
запрет удаления колонки с задачами, загрузка и скачивание вложений, автозапуск
desktop-режима (полный цикл «включить → файл валиден → выключить» на временной
папке), а также запрет встраивать в превью HTML и SVG — в контексте приложения
они выполнили бы свой скрипт.

Отдельно покрыт проектный слой (`tests/test_project.py`): описание доски,
добавление/правка/удаление обновлений, загрузка, переименование, удаление и
скачивание документов, их изоляция между досками, архив документации
(включая защиту от выхода за пределы папки при распаковке), включение и
отключение публичной ссылки, отсутствие утечек между проектами, запрет
встраивать HTML в превью документа и в публичную ссылку, заголовки
`nosniff`/`no-store` у публичных ответов и обновление схемы старой базы
(у неё появляются колонки `description`, `docs_public`, `public_token`

```bash
pip install -r requirements.txt -r requirements-dev.txt

```

GUI-часть (`run_ui`, трей, обработчики окна) юнит-тестами не покрывается —
проверяется вручную запуском `run_desktop.bat`.

## Перед коммитом
Один сломанный JS-модуль роняет всю доску: браузер не грузит граф
зависимостей, страница остаётся пустой, а ошибки в консоли при этом нет.
Чтобы такое не уходило в репозиторий, есть быстрая проверка:

```bash
python check_js.py
```

Она читает `static/js/**/*.js` и зовёт `node --check` для каждого файла —
находит файл и строку с опечаткой. Если Node.js не установлен, проверка
пропускается и не мешает работе.

Проверка запускается автоматически при каждом коммите: `run.bat`,
`run.sh`, `run_desktop.bat` и `run_desktop.sh` при старте ставят
git-хук `pre-commit` сами, копировать вручную ничего не нужно.

Если хук потерялся, он ставится одной командой:

```bash
python check_js.py --install-hooks
```

Обойти проверку в крайнем случае: `git commit --no-verify`.

Если доска всё-таки не открылась, `index.html` покажет красное сообщение
вместо пустого поля и подскажет запустить `check_js.py`; кроме того,
`boot()` в `main.js` пишет ошибку в консоль (F12).
